# P32 — selective KDA-core Q4_K control

## Verdict

**MEASURED PRACTICAL GO on the frozen product-mode gate; not quality
equivalence and not sufficient for four tokens per second.**

P32 changes only five large matrix families in each of Kimi K3's 69 recurrent
KDA layers from Q6_K to Q4_K.  Routed experts, router, shared experts, routed
latent projections, MLA layers, embeddings, output head, slab order, mean
tails, layer budgets, and exact-fallback rules are unchanged.

The 12-prompt native-success gate retained 12/12 tasks and 9/12 token-identical
generations, matching the frozen revision-40 slab policy's task and exact-token
counts.  Median steady decode-row throughput improved 1.089x.  The full suite
wall improved 1.089x and peak host memory fell by 6.94 GiB.

This result earns the selective core representation as an opt-in candidate. It
does not make it the exact/default model: terminal KL remains material and the
suite deliberately uses deterministic thinking-disabled product mode.

## Transformation

The preregistered tensor suffixes are:

- `attn_q.weight`
- `attn_k.weight`
- `attn_v.weight`
- `ssm_g.weight`
- `attn_output.weight`

Only recurrent layers, detected from the model's per-layer K/V head-count
metadata, are eligible.  This yields exactly 69 × 5 = 345 Q6_K tensors.

| Quantity | Source | Candidate |
|---|---:|---:|
| targeted KDA tensor bytes | 23.2155 GiB | 15.9192 GiB |
| complete GGUF files | 594,040,923,616 B | 586,206,586,336 B |
| mapped CPU core at load | 45.34 GiB | 38.04 GiB |
| routed expert qtypes | IQ1_S / IQ2_XXS | unchanged |

The complete GGUF is 7.2963 GiB smaller.  The current experimental artifact
still contains copied expert tensors so that the existing loader can consume it
without a format change.  A future distribution package should avoid
duplicating those copied expert bytes when the authoritative slab bank is
present.

## Quantization provenance

The installed older quantizer did not recognize Kimi K3.  The control used
current upstream `llama.cpp` commit
`01818e4956858fe225a6875aae88b4cbee0b319e` and the narrow patch in
`scripts/patches/llama_cpp_selective_copy_quantize.patch` (SHA-256
`603fa4f35391cdd31f185b96bb3312c6f8a1399415dddd869bfbc367b2d888ac`).
The patch makes `COPY` the per-tensor default while permitting explicit tensor
overrides; it also avoids requesting an importance matrix for tensors whose
type is unchanged.

Apply this zero-context patch to that exact upstream commit with:

```bash
git apply --unidiff-zero scripts/patches/llama_cpp_selective_copy_quantize.patch
```

The deterministic plan and exact anchored tensor rules are generated by:

```bash
python3 scripts/plan_kimi_k3_kda_requant.py \
  /mnt/kimi-k3/models/unsloth-Kimi-K3-GGUF/UD-IQ1_S/Kimi-K3-UD-IQ1_S-00001-of-00014.gguf \
  /tmp/k3-p32-kda-q4k-tensor-types.txt \
  results/k3_p32_kda_requant_plan.json
```

The conversion command was:

```bash
/tmp/llama-k3-quant/build/bin/llama-quantize \
  --allow-requantize --keep-split \
  --tensor-type-file /tmp/k3-p32-kda-q4k-tensor-types.txt \
  /mnt/kimi-k3/models/unsloth-Kimi-K3-GGUF/UD-IQ1_S/Kimi-K3-UD-IQ1_S-00001-of-00014.gguf \
  /mnt/kimi-k3/models/kimi-k3-kda-q4k-p32/Kimi-K3-KDA-Q4_K.gguf \
  COPY 12
```

Conversion wall time was 794.98 seconds.  `COPY` is important: a global Q4
conversion would invalidate this experiment by modifying experts and every
other core family.

## Integrity gate

`scripts/verify_kimi_k3_selective_requant.py` verifies all 2,573 tensor names,
shapes, and qtypes.  It requires exactly the 345 preregistered tensors to change
Q6_K→Q4_K.  It also samples beginning, middle, end, and a deterministic random
window from every one of the 2,228 non-target tensors.  The sampled audit read
31.26 MiB and passed.  A complete byte hash of every non-target tensor is run
as the release-strength gate and recorded in
`results/k3_p32_kda_requant_verification.json`.

## Measured stage result

One frozen 53-token code prompt produced 23 steady autoregressive decode
transitions under the unchanged 1.22-GiB slab policy.

| Stage | Revision-40 core | P32 core | Change |
|---|---:|---:|---:|
| routed preparation median | 802.549 ms | 634.375 ms | **−20.95%** |
| complete transition median | 1,446.729 ms | 1,328.166 ms | **−8.20%** |
| transition rate | 0.6912/s | 0.7529/s | **1.089x** |

The expert-provider median changed 493.997→561.455 ms because the modified
model takes a different route/byte trajectory; it is not evidence that expert
delivery itself regressed.  The end-to-end total remains the decision metric.

The candidate code answer was correct but diverged at the first generated
token, omitting the native Markdown fence.  Aligned-history KL mean/median/p95/
max was 0.0602/0.0140/0.2724/0.7778.  This single prompt earned the wider gate;
it is not the quality verdict.

## Frozen 12-prompt result

The preregistered suite spans factual, code, arithmetic/reasoning, grammar,
translation, and extraction/retrieval prompts.  The exact same calibration,
sidecars, mean tails, fallbacks, and layer-budget table were used.

| Metric | Original core + slabs | P32 core + same slabs |
|---|---:|---:|
| native-success tasks retained | 12/12 | **12/12** |
| token-identical generations | 9/12 | **9/12** |
| mean terminal KL | 0.6849 | 0.6903 |
| median terminal KL | 0.3460 | 0.3667 |
| p95 terminal KL | 2.8427 | 2.5546 |
| max terminal KL | 5.3593 | 5.2584 |
| telemetry wall | 1,018.46 s | **934.82 s** |
| peak host memory | 45.19 GiB | **38.26 GiB** |
| GPU energy | 123.61 kJ | **111.79 kJ** |

The wall-time throughput ratio is 1.0895x and measured GPU-energy reduction is
9.57%.  Terminal rows differ (660 versus 643) after harmless generation
divergences, so the small KL differences must not be interpreted as a paired
proof that Q4_K improves the model.  They show that P32 did not create an
obvious distributional collapse on this gate.

The P32 text differences were behaviorally harmless: `CO₂` instead of the
longer gas name, valid unfenced Python instead of fenced truncated Python, and
a period after `Muchas gracias`.  All task predicates passed, including the
decoy retrieval code `QUARTZ-918`.

## Boundaries and next action

- This is a combined KDA-Q4_K plus frozen slab-policy deployment test.
- It does not establish official K3 benchmark parity; official evaluation uses
  thinking enabled at maximum effort.
- It does not by itself approach four tokens per second.  The measured gain is
  about nine percent.
- Q4_K is not yet a default.  It needs a thinking-enabled benchmark bridge and
  longer generation before a distribution claim.
- The next systems action is to combine this smaller core with an exact
  overlap/offload experiment, keeping the byte policy frozen.  The remaining
  expert-provider and routed-preparation costs are both still large.
