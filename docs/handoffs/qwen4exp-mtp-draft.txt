Qwen4Exp chained MTP delivery

Implementation
QWEN4EXP_MTP_DRAFT defaults to 1. Integers clamp to 1..4; malformed values use 1.
The configured maximum is read once at cache creation. Generation reduces k
near the output/context limit. Each later draft consumes the previous draft
and the MTP layer's last HC residual. Pending verified trunk pairs replace the
speculative MTP KV suffix before the next chain.

One trunk graph verifies [next, draft_1, ..., draft_k]. Its row attention uses
the same position-dependent span as T=1, and its matmuls use the existing
batch-invariant mode. The server samples rows only through the first mismatch
or stopping token, preserving RNG draws, history, EOS and budget substitutions.
The pure prefix function returns the accepted count and emitted trunk tokens.

Persistent token-major F32 GDN states and conv/PLE histories have k+1 slices.
Device-to-device copies from preallocated slice views restore any prefix.
KV/raw-key visibility ends at pos+retained. indexer_blocks is clamped to the
complete retained blocks; rolled-back block completions are recomputed from
replacement raw keys. PLE token tails are restored too. T=1 still uses the
speed branch's stable dense/QSA graphs; verification uses its own workspace.

Rollback storage (36 linear layers, 128x128x48 GDN state, conv 3x10240,
PLE 9x10240; all F32):
 k  bytes         MiB
 1  236077056     225.140625
 2  354115584     337.710938
 3  472154112     450.281250
 4  590192640     562.851563
These are reusable per-cache allocations, not allocations each decode step.
MTP F16 KV adds 2048 * max_ctx bytes for every k. Model weights, graph allocator
workspaces, host logits and metadata are additional and excluded from this table.

Required results
Every smoke must return 0, tokens_identical=1, logits_identical=1, and forced
rollback cache_and_logits_identical=1 with all 4*(k+1) cases. This forces every
retained prefix at all block alignments, checks recurrent/conv/PLE/KV/raw and
pooled-key bytes, then overwrites the rejected suffix and completes its block.
S=2048 additionally crosses the dense/QSA transition. The stable smoke must
report positive QSA replays and identical bits. Server A/B must report exact=True
for short, crossing and long prompts at every k, load a sidecar and log actual
speculation. Compare drafts/accepted/rate/tokens_per_step and decode tok/s;
performance gains are measurements, not prerequisites for exactness.
Repeat smoke with QWEN4EXP_SMOKE_CHUNK=8 to cover chunked MTP prompt catch-up.
GPU equality and throughput have not been tested locally (no GPU).
